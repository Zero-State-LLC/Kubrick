# KUBEVAL-001 intent

## Problem
Kubrick v0.27.14 has deterministic checks and an EP-01 board calibration harness but lacks a cheap automated, cross-task and out-of-sample process to choose and continually requalify models. EP-01 wording was tuned on the same character and dataset, so its reported performance cannot establish generalization. Choosing the lowest advertised token price ignores acceptance rate, retries, latency, and hard canon failures.

## Proposed outcome
Add a proposal-only, budget-capped OpenRouter model-selection and evaluation specification. The future implementation will discover eligible models, benchmark them against frozen evidence, choose qualified per-task champions, and track cost and time to accepted outcomes. Outputs are reproducible comparison receipts and explicitly reviewable routing-policy proposals. This change adds **specification and documentation only**, not a working OpenRouter integration, deployment, payment authorization, or skill behavior.

## Affected users / systems
Hermes operators, Kubrick CLI and QC tools, board vision adapter, offline calibration fixtures, optional provider integrations, release qualification, production spend planning, and Zero-State-LLC project board.

## Constraints / non-goals
- Keep root `SKILL.md` contract, `PROPOSED`, `OBSERVATION`, and `NOT_COMPUTABLE` semantics unchanged.
- Existing hard pre-spend Jev and board gates remain fail closed; benchmark selection never bypasses them.
- No paid model calls, image/video generation, live routing, automatic corpus mutation, Forge authority promotion, or production release changes in this proposal.
- No secrets or private source images in Git. No updates to `references/` or packaged hub mirror for documentation-only changes.
- No new service or deploy/pin workflow; use SQLite, local tools, existing CI for offline deterministic checks.
- Human approval remains required for spend, production promotion and canonical state changes.

## Open questions
Decisions recorded in [the specification](../docs/KUBEVAL-SPEC.md): benchmark partitioning, judge calibration, statistical gates, cost ceilings, provider privacy, capability availability, and how model discovery differs from production route selection. Any unvalidated assumption remains provisional.
